# 用例

性質の違う3つのマージ。どれも同じ手順（分解 → 前提のつながり → 主題 → 選択 → 連続性の担保 → 再構成）を通るが、前提のつながり方が違うので、結果の形も違う。

---

## 用例1：試行の記録と、それを統合した記事

**入力**
- 記事1〜3：同じ動機（〜を自動化したい）を冒頭で述べ、それぞれ方式a・b・cでスキルを作り、試した結果を書いている
- 記事4：a・b・cを比べて良いところを組み合わせ、一つのスキルにした短い記事。動機はほとんど書かれていない

**前提のつながり**
記事4の各章は「aの〜」「bの結果では〜」と、記事1〜3の結果を前提にしている。記事1〜3の動機の章は3回重複している。記事4は記事1〜3の方式を一部置き換えている。

**主題**
依存が記事4に集まっているので、記事4の内容が主題になる：「〜のために、3つの方式を試した結果を組み合わせて新しいスキルを作った」

**選択**
本筋：記事4の全章と、記事4が依存する記事1〜3の章（採った要素の出どころ、捨てた理由を示す結果）。記事1〜3の動機は1回分。
余談：試行中に偶然見つかった、主題と無関係だが面白い挙動。
落とす：各記事の環境構築の細部、重複した動機。

**連続性**
記事4の「3候補のうち」は読者が記事1〜3を読んでいる前提の書き方。a・b・cを短く紹介する節を本筋に加えて穴を埋める。捨てた方式は現在形で書かず、判断の根拠として過去の検討として書く。

**統合目次**
```
1 なぜこのスキルが必要か     ← 記事1〜3の動機（統合）
2 作ったスキル               ← 記事4
3 設計の判断                 ← 記事1〜3の該当章 ＋ 記事4の比較 ＋ 橋渡し
4 評価と限界                 ← 記事4、記事3
5 余談                       ← 記事3の一部
```

## 用例2：同じ対象について別々に書かれた2つの手引き

**入力**
- X：開発チーム向けのデプロイ手順書。環境構築、ビルド、デプロイ、ロールバック
- Y：運用チーム向けの障害対応メモ。監視の見方、よくある障害、ロールバック、エスカレーション

**前提のつながり**
「ロールバック」の章が両方にあり、重複だが手順が少し違う（衝突）。Yの監視の章は、Xのデプロイの章で確立される「どこに何がデプロイされているか」を前提にしているが、Yには書かれていない（穴）。X0の対象読者は開発、Y0は運用（暗黙の前提の違い）。

**主題**
並列に「デプロイ手順と障害対応」とすると連結に戻る。両者が共通に答えている問いを探すと「このサービスを安全にリリースし、問題が起きたら戻す」になる。

**選択**
本筋：ほぼ全章。この組み合わせでは落とすものは少ない。
落とす：ロールバック手順の重複分。

**連続性**
対象読者を「リリースと運用に関わる人」に広げる。ロールバック手順の衝突は、どちらが現行かがわからないのでユーザーに尋ねる（仮に新しい日付の方で書き、明示する）。監視の章の前に、デプロイ構成の章が来るように並べれば穴は埋まる。

**統合目次**
```
1 対象と構成               ← X0, Y0, Xの環境構築の一部
2 リリース                 ← Xのビルド・デプロイ
3 監視                     ← Yの監視
4 障害対応                 ← Yのよくある障害
5 ロールバック             ← X・Yのロールバック（統合）
6 エスカレーション         ← Y
```

並べ方は出典順（X全部、Y全部）ではなく、リリースして見張り、問題があれば戻す、という依存の順になる。

## 用例3：論文草稿の2つの版

**入力**
- 版1：導入、関連研究、手法、実験、考察
- 版2：共著者が書き直した版。導入と手法を書き換え、実験を一つ追加し、関連研究を削っている

**前提のつながり**
版2の手法の章は、版1の手法の章を置き換えている。版2で追加した実験は、版2の手法を前提にしている。版1の考察は版1の手法を前提にしているので、そのままでは版2の手法とつながらない。版2で削られた関連研究の章は、版2の導入の一部の主張の前提になっている（穴）。

**主題**
論文の主張そのもの。版2の導入から一文で取り出せる。

**選択**
本筋：版2の導入・手法・全実験、版1の関連研究（穴を埋めるため復活）、考察。
落とす：版1の手法（置き換え済み）。
余談：論文には余談を置かないので、価値はあるが本筋から外れるもの（版1の手法でしか成り立たない議論）は、報告に「今回入れなかったもの」として残す。

**連続性**
版1の考察のうち、版1の手法を前提にしている部分を、版2の手法の前提で読み替えられるかを確かめる。読み替えられない部分は、新しい事実を作らずにユーザーに指摘する。

---

## 3つの用例の違い

- 用例1は依存が一つの文書に集まっていて、選択と落とすものが多い
- 用例2は文書が並列で、ほぼ和集合になり、主題を上位の問いとして立てるのが鍵になる
- 用例3は置き換えが中心で、古い版の章を前提にした部分の読み替えが鍵になる

どれも、前提が途切れない順序に並べ直す、という点は同じである。
