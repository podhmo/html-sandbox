# Document Merge

## このSkillが解く問題

「これらの文書をマージして」と頼まれたとき、素朴な処理は2つに崩れる。

- **連結**：文書を順に並べる。並びが出典順になり、後の文書が前提にしていることが前に書かれていなかったり、同じ前提が何度も繰り返されたりする。
- **要約**：全部を均等に縮める。どこが本筋かの判断がないので、本筋の細部も枝葉と一緒に削られる。

このSkillでいうマージは次の3つからなる。

1. **分解**：各文書を章ごとの骨子に下ろす
2. **前提の連続性の担保**：統合後の文書で、どの章もその前提が先に示されている状態を作る
3. **再構成**：骨子の上で章を選び、並べ直し、本文に戻す

本文を直接いじらず、骨子の上で構成を決めてから書くのは、前提のつながりが本文のままでは見えにくいからである。

このマージは集合の和とは違う。

- **可換とは限らない。** 文書どうしの関係（どちらがどちらの前提になっているか、どちらが新しいか）によって扱いが変わる。入れ替えれば結果も変わりうる。
- **和集合とは限らない。** 統合文書の主題に寄与しないものは落としてよい。取りこぼしは自然に起こる。価値のあるものは最後に「余談」として拾う。

## 全体の流れ

1. 分解：各文書を章カードにする
2. 前提のつながりを把握する：章どうしの依存を、文書をまたいで書き出す
3. 統合文書の主題を決める
4. 章を選ぶ：主題から依存をたどって本筋を決め、残りを余談か落とすかに分ける
5. 前提の連続性を担保する：衝突・置き換え・穴を処理し、必要なら橋渡しを置く
6. 統合目次を組み立てる
7. 章ごとに本文を書く
8. 検証する

---

## 1. 分解：章カードにする

考える単位は章（短い文書なら節や話題のまとまり）。一文ずつに分解すると全体の構造が見えなくなる。見出しのない文書や、見出しが内容と合っていない文書は、話題の切れ目で区切る。

各章について次を持つカードを作る。

- **ID**：`X1`, `X2`, … / `Y1`, …
- **要旨**：この章が言っていることを一〜二文で
- **要点**：主な項目を数個。何が書いてあるかがわかれば十分（詳細は原文にある）
- **前提とするもの**：この章を読むのに、読者が先に知っている・受け入れている必要があるもの（概念、定義、決定、先行する結果、背景事情）
- **確立するもの**：この章を読んだ読者が新たに得るもので、他の章が使いうるもの

「前提とするもの」と「確立するもの」が、章をつなぐ接点になる。章Bの前提が章Aで確立されていれば、AはBより前に来る必要がある。

文書全体が当然としていて、どの章にも書かれていない前提（対象読者、スコープ、時点・版、立場、用語の意味）は、`X0` のようなカードに書き出す。文書を統合すると、この暗黙の前提どうしがよく衝突する。

章どうしが部分的に重なる・食い違う箇所では、その章の中に一段降りて、節や段落の単位で比べる。全体を細かく刻むのではなく、問題のある場所だけ解像度を上げる。

## 2. 前提のつながりを把握する

章カードの「前提とするもの」と「確立するもの」を結び、章どうしの依存を書き出す。**文書の中だけでなく、文書をまたいで結ぶ**ことが大事である（例：`Y2 は X3 で確立された〜を前提にしている`）。

あわせて、文書をまたぐ次の関係を拾う。

- **重複**：同じことを扱う章。どちらが詳しいか、どちらにしかない内容は何か
- **包含**：一方の章が他方の章の一部を詳しく書いている
- **置き換え**：一方の章が他方の章の内容を更新・撤回している（新しい版、後の決定、改めた結論）
- **衝突**：両立しない内容。暗黙の前提の違い（対象、時点、用語）から来る見かけの衝突も含む
- **用語の揺れ**：同じ概念に別の言葉、同じ言葉で別の概念

文書どうしの関係（どれがどれの前提になっているか、どれが新しいか、どれが中心か）は、決めつけずに、この依存と関係から読み取る。

## 3. 統合文書の主題を決める

統合文書が何を言う文書なのかを一文で書く。章を選ぶ基準と、並べる順序の軸になるので、構成を組む前に決める。

主題はユーザーの依頼と、ステップ2で見えた依存の形から決める。依存がどこかに集まっている（多くの章が前提として流れ込んでいる）なら、そこが主題の候補になることが多い。

「Xの内容とYの内容」のように並列に書いた主題は、そのまま連結に戻りやすい。並列に見えるときは、両者を一つにまとめる上位の言明（両者が共通に答えている問い、両者を合わせて言えること）を探す。

主題の立て方で結果が大きく変わり、ユーザーの意図が読み取れないときは、構成を組む前に一文で確認する。

## 4. 章を選ぶ

和集合を取らない。選ぶ基準は**主題からの依存**である。

**本筋を決める。** 主題を直接述べる・支える章を本筋に入れる。本筋の章が「前提とするもの」をたどり、それを確立する章を本筋に加える。これを繰り返し、たどり着いた章が本筋になる。

**残りを振り分ける。** 本筋に入らなかった章を二つに分ける。

- **余談**：主題を支えはしないが、読者にとって価値がある（思わぬ発見、教訓、別の場面で使えそうな内容、未解決の問い）
- **落とす**：主題にも読者にも寄与しない（他の章に置き換えられた記述、重複の残り、本筋から外れた細部）

迷ったら余談に入れる。余談が本筋より長くなるなら、主題の立て方か選び方を見直す。

## 5. 前提の連続性を担保する

統合文書の中で、どの章もその前提が先に示されている状態を作る。ここがマージの中心であり、連結との違いが出るところである。

**暗黙の前提を揃える。** `X0`・`Y0` などを比べ、統合文書の対象読者・スコープ・時点・用語を一つに決める。一方が他方を含むなら広い方を採り、独立なら両方を覆うように広げ、衝突するなら次の「衝突」と同じように処理する。

**衝突を処理する。** 次のどれかを選ぶ。
- 場合分け：両方が別の条件で正しいなら、条件を示して両方を書く
- 一方を採る：一方が古い・誤り・範囲外と判断できるなら採る。採らなかった側は報告に残す
- ユーザーに尋ねる：方針や事実の判断が必要で、文書から決められないとき

**置き換えを処理する。** 古い内容を新しい内容と同列に、現在形で書かない。古い内容が本筋に必要なのは、新しい内容がなぜそうなったかを示す場合だけで、そのときは経緯として書く。

**穴を埋める。** 本筋の章が前提とするもののうち、本筋のどこでも確立されていないものを探す。元の文書では別の文書を読んでいる前提だった、書き手が省いていた、などで起こる。

- 本筋の外にそれを確立する章があれば、本筋に加える（ステップ4に戻る）
- なければ、短い**橋渡し**を置く。橋渡しは、すでにある内容どうしの関係（なぜこの話がここに来るか、どの章を受けているか、どの場合の話か）を示すだけにし、**新しい事実を持ち込まない**
- 埋めるのに、どの文書にもない内容が必要なら、作らずにユーザーに指摘する

**重複をまとめる。** 同じ前提や同じ説明が複数の文書にあるなら一つにする。より正確・具体的な方を採り、もう一方にしかない細部を加える。

## 6. 統合目次を組み立てる

統合文書の目次を作る。各章に次を書く。

- 新しい章番号と見出し
- **出典**：どの元章から構成するか（例：`第3章 〜 ← X3, Y2.1 ＋ 橋渡しB1`）

並び順の第一の条件は、**どの章も、その前提を確立する章より後に来ること**。この条件で決まらない部分は、主題と読者に照らして自然な順（全体→部分、背景→決定→実施、結論→根拠、時系列など）で決める。結論を先に置くか後に置くかも、文書の種類と読者で決める。

見出しは新しい構成に合わせて付け直す。元の見出しや文書名をそのまま並べると連結の痕跡になる。

余談は最後に置き、本筋でないことがわかる見出しにする。

文書が長い場合や判断が多い場合は、本文を書く前に、目次と出典、落とすものの一覧をユーザーに見せて確認を取ってよい。

## 7. 章ごとに本文を書く

目次の上から一章ずつ書く。

- 選択は章の単位で行い、**選んだ章の中身は要約しない**。具体例・数値・手順・コード・図表の参照は持ってくる
- 章の冒頭で、その章が前のどの章を受けているかが読者にわかるようにする
- 文体・トーン・人称・表記は一つに揃える。指定がなければ、中心になる文書に合わせる
- 用語はステップ2で決めた統一表記を使う
- 出典の痕跡（「別の資料では」「前回の記事では」）は残さない。一つの文書として書かれたように読めるようにする
- 章をまたぐ参照は新しい章番号で付け直す
- 余談は短く、本筋から独立して読めるように書く

文書が長いときは一章ずつ書き進める。全体を一度に書こうとすると後半が要約に崩れやすい。

## 8. 検証する

- **前提の連続性**：頭から読んで、どの章もその前提が先に示されているか。別の文書を読んでいることを前提にした書き方が残っていないか
- **主題**：読んだ人がステップ3の一文を言えるか
- **本筋の必要性**：本筋のどの章も、主題につながる依存の経路の上にあるか
- **置き換え・衝突**：古い内容が現役のように書かれていないか。衝突がすべて処理されているか
- **橋渡し**：新しい事実を持ち込んでいないか
- **要約への崩れ**：本筋の章で、元にあった具体的な内容が抜けていないか

## 出力

1. **統合文書**（主成果物）。形式はユーザーの指定、なければ元の文書の形式に合わせる
2. **マージ報告**（短く）：
   - 主題の一文
   - 章の対応表：新しい章ごとに、どの元章から作ったか
   - 余談に回したもの、落としたもの（一行ずつ。ユーザーが復活させたいものを選べるように）
   - 衝突・置き換えの処理、橋渡しを入れた箇所
   - ユーザーに判断を求める点（あれば）

## 用例

文書の組み合わせによって、前提のつながり方も、主題の立ち方も変わる。`references/examples.md` に、性質の違う用例をいくつか載せている。手順に迷ったときや、自分の判断が連結・要約に寄っていないか確かめたいときに読む。用例は手順の当てはめ方を示すもので、型として真似るものではない。
