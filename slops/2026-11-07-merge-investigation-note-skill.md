# 三つの試作から、技術調査の記事を書くスキルを一本にした

> [!NOTE]
> 執筆: Claude Code（Opus 5.5）。作業したのと同じセッションで書いている。

## 依頼と、始めた時点の材料

依頼は、直近の slops と `.agents/skills` を読み、Claude 用に特殊化したスキル（`write-slops-investigation-note--claude`）をベースにして `write-slops-investigation-note` を作ること。途中で、判断を仰ぎたいところは質問で聞くこと、今日の記事を全部しっかり読んでから判断すること、の二つが加わった。

始めた時点で `.agents/skills/` には、base の write-slops と、同じ依頼を三つのエージェントが実行した試作が並んでいた。`--claude`（82 行）、`--gpt`（89 行）、`--gemini`（38 行）で、`AGENTS.md` は「試作のどれか一つを選ぶ」と案内していた。今日の slops は三本あり、それぞれが自分の試作の経緯と、ほかの試作との比較を持っている。

- Claude Code の [技術調査のあとに書く記事のスキルを、issue の下書きから作った](2026-11-07-investigation-notes-skill.md)。README と、比較の 01〜03。
- Codex の [技術探索後の記事を書くスキルを作り、元の対話から指定を絞り直した](2026-11-07-exploration-notes-from-issue-133.md)。README と、比較の 01・02。
- Gemini の [技術調査ノートのための slops 執筆スキルを作る](2026-11-07-write-slops-investigation-notes.md)。

## 総評の推奨どおりに足した最初の版

最初に読んだのは、三つのスキルと、Claude の README と総評（`03-overall.md`）だけだった。総評には、一本にするならこう、という推奨がある。Claude 版の短さと記事側の決まり（範囲外の選択肢の書き方、`docs/sketch/` との分担、依頼を書き直してよい理由）を土台にして、GPT 版から次のものを取り込む。

- 代替案を残す基準（結果の条件・限界・再現に関係するもの）と、失敗した試行・検討したが実行しなかった案・あとで気づいた可能性の三分類
- 後から加わった条件を最初から分かっていたように書かないこと
- 結果の評価のしかたを変えた途中の変更も残すこと
- 回避策を既定では暫定扱いにしないこと
- 余談を任意にすること
- `AGENTS.md` からの案内

これに沿って Claude 版を書き換えた。そのとき、推奨には入っていない GPT 版の文もいくつか一緒に持ち込んでいた。表で条件を比べてよいこと、関係のない条件は書かないこと、一度の成功を互換性の保証や最善の解にしないこと、部分的な結果や否定的な結果も答えになること、余談の節にしか答えがない状態にしないこと。

総評が依頼した人に預けていた点が二つあったので、質問した。一つはペダンティックの禁止で、Claude 版は理由ごと戻し、Gemini 版はモデルごとの語り口の差を損なうとして外していた。答えは「残す」。もう一つは三つの試作の扱いだった。description がほぼ同じなので、Claude Code のスキル一覧に調査記事用のスキルが四つ並び、どれが選ばれるかが曖昧になる。答えは「残して description を変える」。試作の description は「比較の記録として残した試作。名前で指定されたときだけ使う」に書き換え、`AGENTS.md` は統合版を既定として案内するように直した。ここまでを `489809d` でコミットした。

## 今日の記事を全部読んで、足しすぎた分を外した

コミットのあとで、今日の記事を全部しっかり読んでから判断するように、と言われた。まだ読んでいなかった Claude の 01・02、Codex の README と 01・02、Gemini の記事を読んだ。

読んでみると、最初の版で一緒に持ち込んだ文には、二つの記事が先に釘を刺していた。Codex の 01 は「すべての条項を足すと、両方の調整で減らそうとした義務を再び増やす危険がある」と書き、統合するなら、まずその調査で必要な差を選びたいとしていた。Claude の 01 は、GPT 版にある「渡す前の確認」や「新しい実験や公開を許可しない」のような作業手順の項目は入れないほうがよい、と書いていた。余談の節にしか答えがない状態にしない、という文は、GPT 版では渡す前の確認の一項目だった。

総評の推奨リストに入っていなかった五つの文は、どれもこの警告にあたると判断して外し、`1d3c3b9` でコミットした。部分的な結果の文は、Claude 版の「答えられていない部分があればどこかを書く」とほぼ重なっていた。互換性の保証の文は、既定で暫定扱いにしないことの言い足しだった。どちらも、外しても失われるものは少ない。

Gemini 版から取り込むものも考え直した。Codex の 02 は、冒頭の「意図と環境の具体的な摩擦に焦点を当てる」を、入口として分かりやすいと評価している。一方、Claude の総評は、Gemini 版から文面として取り込みたいものは短さ以外にない、としていた。この一文は、Gemini 版がペダンティックの禁止を外したときに代わりに置いたものだ。禁止を残すと決めた統合版では役割が重なると考え、入れない案を推して質問した。答えは「入れない」だった。

Gemini の記事について 01・02 が指摘していた点（番号付きリスト、文を箱にした図、確かめていない効果を確かめたように書いたこと、PR 番号の誤り）は、記事の書き方の問題で、スキルの文面には関係しないので触っていない。

## 元の対話と突き合わせた

この記事を書き始めたところで、依頼した人が、三つの試作のどれもが参照していた元の対話を貼ってくれた。issue #133 のコメントにあった下書きができるまでの対話で、統合版をこれと突き合わせた。

いちばん効いたのは、代替案を残す基準だった。対話で依頼した人が欲しいとしていたのは「どういう選択肢を捨てたのか」で、「なぜホスト側のドライバ更新を人間に頼まなかったのか」ではない。対話の中のシミュレーションは、捨てた案の一つ目にホスト側のドライバ更新を挙げている。この案は範囲外としてすぐに外れたもので、作業の進路は変えていない。Claude 版の基準（実際に検討して進路を変えたもの）ではこの案は落ち、GPT 版の基準（結果の条件・限界・再現に関係するもの）では残る。Claude の 01 が、Codex の比較を読んで認めていた点でもある。統合版は二つを「または」でつないでいるので、この案は残る。

ほかの点も対話と合っていた。ペダンティックの禁止は、名前を investigation-notes に決めるときに、依頼した人が「ペダンティックにならなければよいが」と言ったことから入っている。依頼を書き直してよい理由の二点は、依頼した人が自分で挙げたもので、Claude 版から引き継いでいる。途中の調整について完全なトレースは要らない、という一文も対話のとおり。

迷ったのは余談だった。対話では、余談は結びのあとに別の章として置くほうが「うれしいかも」と言っている。必須にした Claude 版と Gemini 版はこれを節の存在の要求と読み、任意にした GPT 版は置き場所の好みと読んだことになる。同じ対話には「不要なものを必須にして作業を縛りたくない」という線引きもあるので、統合版は任意のまま、置くなら結びのあと、とした。

## AGENTS.md の案内を外した

記事を書き終えたあと、依頼した人から、`AGENTS.md` の案内はそもそも要らないと言われた。技術的な備忘録を書かせたいときは、依頼した人がスキルを直接指定するからだ。総評の推奨に従って足した案内と、試作三つへのリンクを外し、`AGENTS.md` には write-slops の紹介と、用途ごとの派生スキル（`write-slops-*`）があり、名前で指定されたときだけ使う、という一文だけを残した。

## できたもの

スキルは [.agents/skills/write-slops-investigation-note/SKILL.md](../.agents/skills/write-slops-investigation-note/SKILL.md) にある。`agents/openai.yaml` も試作に合わせて付けた。`.claude/skills` は `.agents/skills` へのシンボリックリンクなので、Claude Code からも同じものが見える。Claude 版からの差分は次のとおり。

| 項目 | Claude 版 | 統合版 | 出どころ |
| --- | --- | --- | --- |
| 残す代替案 | 実際に検討して進路を変えたもの | それに加えて、結果の条件・限界・再現を説明するもの | GPT 版、元の対話 |
| 代替案の区別 | なし | 失敗した試行、検討したが実行しなかった案、あとで気づいた可能性を分ける | GPT 版 |
| 記録にない理由 | 補わない | 補わず、不明と書く | GPT 版 |
| 回避策 | 条件付きで書く | 条件付きで書き、既定では暫定扱いにしない | GPT 版 |
| 途中の変更 | 次にしたことを変えたもの | 結果の判断のしかたを変えたものも。後から加わった条件を最初からあったように書かない | GPT 版 |
| 余談 | 必須 | 任意 | GPT 版、元の対話 |
| ペダンティックの禁止 | あり | あり | 依頼した人の判断 |
| 案内 | description だけ | `AGENTS.md` は派生スキルがあることだけを書き、使うのは名前で指定されたとき | 依頼した人の判断 |

この記事は統合版の節の順で書いた。題材はまたスキル作りで、第 2 節の「捨てた道と理由」は、権限やバージョンではなく、記事の指摘と依頼した人の答えになっている。技術調査の題材で、Claude 版より必要な代替案がよく残るかは、まだ確かめていない。確認は `make test-go`、`tools/slops-nav` でこの記事と前の記事の prev/next がつながっていることの確認、svg-gen の lint と PNG での目視まで。

## 余談

- 三つの試作は消していない。前の三本の記事は、試作のパスやコミットに固定したリンクで参照している。試作のスキル本文は当時のままで、description だけを変えた。
- 比べるなら、三本の記事の総評がそろって書いていたとおり、次に技術調査をしたセッションから fork を起こし、統合版と Claude 版で同じ材料から書かせるのがよさそうだ。図の位置に置いたドライバ更新のような案が、実際に残るかどうかを見ることになる。
