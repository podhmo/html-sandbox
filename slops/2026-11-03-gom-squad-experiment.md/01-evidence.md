# 観察と含意の対応表

README 本文の推測を支える観察の一覧。「観察」はリポジトリから直接読める事実、「含意」はこの記事の読み（推測）で、両者は別物として扱う。

| 観察（リポジトリ内の事実） | 含意（推測） |
| --- | --- |
| TODO.md に「読み方（オーケストレーター向け）」節。タスク ID、依存欄、「依存がすべて `[x]` になったら並列着手可」「1 タスク = 1 worktree = 1 squash merge」 | タスク表は人間の備忘録ではなく、オーケストレーターがワーカーに仕事を切り出すための構造化インタフェース |
| docs/sketch/2026-11-03-wave3-prompts.md に、wave 単位のタスク分割と子セッション向けプロンプト草案がコミット済み | オーケストレーション自体が成果物として記録されている。プロンプトの改版履歴 = 手続きの実験ログ |
| skills/gom-agent-guide: 「LLM の事前知識に Gom はほぼ存在しない」を前提にした言語ツアーと間違い集。`.devin/skills/` へ symlink | 利用者より先にエージェントへの onboarding を整備している。読者は機械 |
| decisions/ 79 件。`状態: draft` で起票 → prototype 検証 → sketch に結果 → 状態更新。覆すときは旧 decision を消さず Supersedes 参照 | 決定の「証拠付き履歴」を機械的に辿れる形にして、後続セッションの再判断コストを下げている |
| sketch/ 57 件、problems/ 50 件、implementation-gaps.md 台帳。「1 件 1 ファイル、ファイル名は変えない」 | 揮発するセッションの代わりにリポジトリが長期記憶を持つ。リンク安定性はエージェントの検索のため |

| V-2..V-5: gomgen 生成器、eval-vs-compiled 差分 fuzz、HM 推論 witness オラクル、fmt 往復 fuzz。divergence / 既知バグは専用レジストリ | 「正しさ」を人間の diff 閲覧に頼らず機械判定する品質ゲート。squad の成果検査を自動化する布石 |
