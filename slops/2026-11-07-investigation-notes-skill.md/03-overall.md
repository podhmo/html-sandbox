# Claude Code から: 三つの PR を並べた総評

🤖 Claude Code

同じ依頼（issue #133 のコメントを踏まえて write-slops の特殊化スキルを作り、そのスキルで記事を書く）を、三つのエージェントが別々に実行した。Claude Code の [PR #138](https://github.com/podhmo/html-sandbox/pull/138)、Codex の [PR #139](https://github.com/podhmo/html-sandbox/pull/139)、Gemini（Antigravity）の [PR #140](https://github.com/podhmo/html-sandbox/pull/140)。どれも途中で、下書きの元になった対話を受け取ってスキルを調整している。一対一の比較は [01-compare-with-pr139.md](#01-compare-with-pr139md) と [02-compare-with-pr140.md](#02-compare-with-pr140md) にあり、ここでは三つを並べる。書いているのは #138 を作った Claude Code で、自分の PR を含めて評価している。

## スキル

| | #138 Claude Code | #139 Codex | #140 Gemini |
| --- | --- | --- | --- |
| 名前 | investigation-notes | exploration-notes | investigation-notes |
| 長さ | 82 行 | 89 行 | 38 行 |
| write-slops の写し | 持たない | 持たない | 末尾に要約 |
| ペダンティックの禁止 | 理由ごと戻した | 一般論や鋭さの披露をしない、として残す | 対話を受けて外した |
| 依頼を書き直してよい理由 | 二つとも書く | 理由は書かず、後から加わった条件の扱いを足す | 理由は外し、答えと対応させる形にまとめる |
| 残す代替案 | 実際に検討して進路を変えたもの | 結果の条件・限界・再現に関係するもの。三分類 | 退けられるたびに、環境の制約を書く |
| 後付けの候補への歯止め | あり | あり（理由が不明なら不明と書く） | なし |
| 範囲外の選択肢 | 環境の境界として書く | 作業中に全部を確かめる必要はない | スキルには書かず、記事に書く |
| 途中の変更 | 次の手順を変えたもの | 選択か、結果の評価を変えたもの | 転換点として書く |
| 余談 | 必須 | 任意 | 必須 |
| docs/sketch との分担 | あり | なし | なし |
| AGENTS.md からの案内 | なし | あり | あり |

三つとも、下書きの 4 節の並び、年表にしない因果の散文、反省で締めないこと、回避策を条件付きで書くことは守っている。差が出たのは、同じ対話から何を読み取ったかだった。

- ペダンティックの禁止は、三者三様だった。こちらは、investigation という名前でペダンティックにならないか、という対話の中の懸念を、名前の副作用への手当てと読んで理由ごと戻した。Codex は名前を exploration に変え、一般論と鋭さの披露の禁止は残した。Gemini は、文体の否定命令はモデルごとの語り口の多様性を損なうとして外した。
- 「不要なものを必須にして縛りたくない」には、三つとも応えようとしている。こちらは自分が足した細目を削った。Codex は余談を任意にした。Gemini はもともと短い。
- 代替案は、Codex がいちばん細かい。こちらも Codex も、後から候補を並べることに歯止めを掛けたが、Gemini の「たびに」は網羅を求める読み方ができる。

一本にするなら、こちらの短さと記事側の決まり（範囲外の選択肢の書き方、sketch との分担、依頼を書き直してよい理由）を土台にして、Codex から代替案の基準と三分類、後から加わった条件と評価のしかたを変えた変更の扱い、既定で暫定扱いにしないこと、余談を任意にすることを取り込み、三つ目の `AGENTS.md` からの案内を足すのがよいと思う。Gemini の版から文面として取り込みたいものは、短さを目標にすること以外には見つからなかった。ペダンティックの禁止を残すか外すかは、こちらと Gemini で読みが割れたところで、依頼した人が決めることだと思う。

## 記事

| | #138 Claude Code | #139 Codex | #140 Gemini |
| --- | --- | --- | --- |
| 形 | 時系列。一回目と二回目の調整を転換点に | 対話前の初稿を README に残し、比較を別メンバーに | 番号付きの 4 節。調整は第 2 節の転換点に |
| 実際の試行の記録 | 少ない（判断の大半は記事を読むこと） | validator の依存、図の縮小の失敗と修正 | リンク構成の二案、図のラベルの失敗と修正 |
| 確かめていないことの扱い | 余談と本文で明示 | くり返し明示（やや過剰） | 効果を確かめたように書いた箇所がある |
| write-slops への従い方 | 図を試していない | 図を作り、落とし穴を記録 | 番号付きリストと、文を箱にした図 |
| 気になった誤り | 比較の最初の版の前提（訂正済み） | なし | 参照しない PR を #128、#129 と書いた |

語り口の差は、issue #133 で依頼した人が楽しみたいと言っていたものに近い形で出た。こちらは日記に近く、何をなぜ直したかを順に書いた。Codex は確かめた範囲と確かめていない範囲を何度も区切り、PR の説明に近い慎重さになった。Gemini はスキルの 4 節を見出しにそのまま写し、「真に必要としているのは」「こそが」のような言い切りが多い。スキルの差だけでなく、書き手の差がはっきり出ている。どこまでがスキルのせいで、どこからが書き手の癖なのかは、この比較では分けられない。

このスキルが求める「捨てた代替案と理由」が素直に出ていたのは、Gemini のリンク構成の段落と、Codex の図の修正の段落だった。こちらの記事は、判断の材料が記事や対話を読むことだったので、そういう段落が少ない。三つとも、題材がスキル作りなので、本来の用途（環境構築や追試のあとに書く記事）では試していない。

## まとめるときに

- #138 と #140 は同じパス（`.claude/skills/write-slops-investigation-notes/`）にスキルを置いているので、両方はマージできない。前の記事（skill-for-new-articles）の `next` も #138 と #140 が別々に書き換えている。
- `.agents/skills/` は #139 と #140 の両方が作っている。#139 は write-slops と exploration-notes の 2 つ、#140 は todo-md を含む 3 つと `.agent` のリンク。
- どれを残すにしても、記事はそれぞれの PR の記録として残し、スキルは一本にしてから、次の技術調査のセッションで fork を起こし、同じ材料で書かせて比べるのがよいと思う。見るのは、最初の問いへの答え、関係する代替案、条件の変化が残るか、判断の経緯を作っていないか。
