# preview 用の Markdown 記事の作成依頼

次のテーマについて、日本語の Markdown 記事を一つ書いてください。

- テーマ: （ここに書く）
- 想定する読者・使う場面: （ここに書く）
- 参照する材料、確認できた事実、未確認のこと: （ここに書く）

回答を html-sandbox の `/preview` に貼って確かめます。次の形式で回答してください。

- 回答は記事の Markdown 本文だけにしてください。挨拶、形式の解説、回答全体を囲むコードブロックは不要です。
- 最初に `#` の見出しでタイトルを書いてください。front matter は不要です。
- 見出しは `#` から `#####`、箇条書きは `- ` を使ってください。段落、引用、区切り行のある表、インラインコード、通常のリンク、バッククォート三つのコードブロックを使えます。
- 強調、番号付きリスト、Markdown の画像記法、HTML の直書き、Mermaid には頼らないでください。このサイトは Markdown の小さなサブセットを扱います。
- 図が説明に役立つ場合は、短い SVG を本文中に埋め込んでください。必ず開始行を ` ```svg ` とし、両端の空白を除いて、小文字の言語名 `svg` を付けてください。言語なし、`xml`、`html`、`SVG` のコードブロックでは画像になりません。
- SVG は `<svg xmlns="http://www.w3.org/2000/svg" viewBox="…">` から始まる完全な要素にし、終了タグの次の行をバッククォート三つだけにして閉じてください。SVG 自体を画像記法や別のコードブロックで包まないでください。
- 図は矩形、線、短いテキストなどで簡潔に表現してください。通常のフォントに任せ、フォントデータの埋め込み、外部フォント、文字のパス化で見栄えを揃える処理はしないでください。文字サイズや配置の指定は必要な範囲で構いません。
- インラインの図の線と文字には `currentColor` を使えます。スクリプト、イベント属性、`foreignObject`、外部リソースを含めないでください。
- 外部の資料にリンクするなら `https://` の URL を使ってください。相対リンクが必要な場合は、プレビューでは `posts/preview.md` が基準になることを踏まえてください。
- 材料から確認できることと、推測や提案を分けてください。確認していない数値や、書き手が決めていない今後の予定は補わないでください。

図を入れる場合の囲み方は次の通りです。これは記法の例なので、図の内容はテーマに合わせて変えてください。図が不要なら省いてください。

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 180 64" width="180" height="64" role="img" aria-label="入力から結果への流れ">
  <g fill="none" stroke="currentColor" stroke-width="1.5">
    <rect x="4" y="12" width="60" height="40" rx="4"/>
    <path d="M70 32h38m-6-6 6 6-6 6"/>
    <rect x="116" y="12" width="60" height="40" rx="4"/>
  </g>
  <g fill="currentColor" font-size="14" text-anchor="middle">
    <text x="34" y="37">入力</text>
    <text x="146" y="37">結果</text>
  </g>
</svg>
```
